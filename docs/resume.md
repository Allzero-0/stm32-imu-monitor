# 简历怎么写这个项目

## 一、项目经历：可直接粘贴的版本

### 版本 A · 标准版（推荐，占 4 行）

```
基于 STM32F103 的姿态采集与上位机监控系统            2026.09 - 2026.10
· 硬件：STM32F103C8T6 + MPU6050 六轴传感器 + 上位机（Python）
· 下位机：寄存器级开发（无 HAL 库），TIM2 定时 200Hz 采样，软件 I2C 突发读取
  六轴数据，ADC 三通道扫描 + DMA 循环搬运；互补滤波解算姿态角
· 通信：自定义二进制帧协议（帧头+类型+序号+时间戳+CRC8 校验），串口 DMA
  发送，100Hz 上传，带宽占用约 34%
· 上位机：Python 串口解析 + 内置 HTTP 服务，浏览器端原生 Canvas 绘制实时
  曲线与 3D 姿态，支持 CSV 记录与命令下发（校准/暂停/状态查询）
```

### 版本 B · 精简版（项目多、位置不够时用）

```
STM32 姿态采集系统 | 独立完成
STM32F103 + MPU6050，200Hz 采样，软件 I2C + ADC/DMA 采集，互补滤波姿态解算；
自定义串口二进制协议（CRC8 校验）100Hz 上传；Python 上位机实时曲线 + 3D 姿态显示。
寄存器级开发，代码开源在 GitHub。
```

### 版本 C · 投电力/继保类岗位时的改写（把技术点往"测量、可靠性"上靠）

```
STM32 多路数据采集与监控系统 | 独立完成
· 面向"多路模拟量 + 数字量采集上传"场景，实现 3 路 ADC（含芯片内部温度）
  与六轴传感器的同步采集，200Hz 采样率下 CPU 占用低于 15%
· 设计带 CRC 校验与序号的二进制通信帧，可实时统计丢帧率与误码率，
  具备通信异常自动恢复能力（I2C 总线恢复 + 传感器重初始化）
· Python 上位机实现实时曲线、数据记录（CSV）与远程命令下发
```

> 投国网/南自这类单位，把关键词往**采集、监测、通信可靠性、故障自恢复**上靠，
> 比强调"姿态解算/无人机"更对味。同样的代码，讲法不同。

## 二、技能栏怎么写

```
专业技能：
· 嵌入式：熟悉 STM32F1 系列（Cortex-M3）裸机开发，能直接操作寄存器配置
  RCC/GPIO/USART/I2C/ADC/DMA/TIM；了解中断优先级与 DMA 传输机制
· 通信协议：熟悉 UART、I2C 时序；了解自定义应用层协议设计（校验、帧同步）
· 语言：C（熟练）、Python（熟练，用于数据处理与上位机）、熟悉 Git
· 工具：arm-none-eabi-gcc 交叉编译工具链、Makefile/Shell 构建脚本、
  ST-Link + OpenOCD 烧录调试
· 其他：能阅读英文数据手册（RM0008、MPU6050 Datasheet）
```

**用词分寸**：只写"熟悉/了解/能"，不要写"精通"。"精通 STM32"这种话
被有经验的面试官一听就知道是背的，后面全是坑。

## 三、GitHub 链接怎么放

1. 简历右上角个人信息区放一行：`GitHub: github.com/你的用户名`
2. 项目经历里写：`代码开源：github.com/你的用户名/stm32-imu-monitor`
3. **README 就是你的第二份简历**，务必保证：
   - 首页有清晰的硬件接线表（让人一眼看出是真的做过）
   - 有目录结构、有编译步骤
   - 有"设计决策"或"踩坑记录"章节 —— 这是区分"抄的"和"自己做的"的关键
4. 提交记录要干净真实，建议分成有逻辑的几次 commit：
   ```
   feat: 添加 RCC 时钟配置与 SysTick 时基
   feat: 实现 USART1 DMA 发送与中断环形接收
   feat: 添加软件 I2C 驱动与总线恢复机制
   feat: 实现 MPU6050 驱动与零偏校准
   feat: 添加 ADC 多通道 DMA 采集
   feat: 实现互补滤波姿态解算
   feat: 定义串口帧协议与 CRC8 校验
   feat: 实现 Python 上位机与可视化页面
   docs: 补充接线说明与面试问答
   ```
   一口气 `git add . && commit -m "first"` 也行，但分次提交看起来更像真实开发过程。

## 四、绝对不能写的东西

| 不能写 | 原因 |
|---|---|
| "精通 STM32 / 精通嵌入式" | 一问细节就露馅，反而扣分 |
| 把没跑通过的写成"已验证/已量产" | 面试官让你现场演示就完了 |
| 虚构获奖、成绩、实习职责 | 背调或细问就穿帮 |
| 把教程/开源项目的代码说成自己写的 | 面试官常问"这段为什么这么写" |
| 写"负责系统架构设计" | 一个人做的小项目谈不上架构 |
| 夸大参数（比如把 100Hz 写成 1kHz） | 一个追问就崩 |

**特别提醒**：本项目在你买板子实测之前，**不要**在简历上写"已完成硬件联调"。
现在可以写"已完成固件开发与协议验证，硬件联调进行中"。
买块板子接上，跑通一次，就可以改成完成时态。
板子加下载器不到 40 块，这一步省不掉。

## 五、面试前必须做的 5 件事

1. **真的把板子跑起来一次**，记住串口打印的启动信息长什么样。
2. **把 README 里的每个数字背下来**：采样率 200Hz、上传 100Hz、
   Flash 8836 字节、波特率 115200、CRC 多项式 0x07。
3. **能徒手画出系统框图**（传感器 → MCU → 串口 → 上位机），
   面试官让他画框图时画得出来，可信度立刻上一个档次。
4. **准备一个"踩坑故事"**（推荐讲 CRC 校验范围写错、或外部晶振回退这个），
   有具体错误、有排查过程、有修复方式 —— 这比"我能吃苦"管用得多。
5. **用 `--sim` 模式把上位机演示流程跑熟**，如果面试官允许，
   打开浏览器给他看实时曲线和 3D 姿态，效果远超口头描述。

## 六、如果被问"这项目有什么用"

别慌，这是压力问题，不是否定。可以这样答：

> "它是一个完整的数据采集链路的验证平台：传感器采集 → 片上处理 → 可靠传输 →
> 上位机呈现。这套链路在电力设备状态监测、环境监测终端里是通用的，
> 换一个传感器就是另一种设备。我做它的目的就是把这条链路从头到尾走通一遍，
> 每个环节的取舍都能说清楚。"
